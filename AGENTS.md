# AGENTS.md

- Content gating goes through `useContentAccess().ensureContentAccess({ source, sample })`; pass a stable sample id from `src/lib/freeSamples.ts` so free-sample claims (table `free_content_claims`, one row per user and kind) stay consistent across screens. Why: one place decides subscription vs free sample vs paywall.
- Pure business rules live in `src/lib/` and are tested with `bun test` under `tests/` (outside `src` so the app typecheck ignores `bun:test`). Why: no test framework is installed in the app.
- Neo Explica stories: one row per story in `neo_explica` (folder `pasta` in private bucket `neo-explica`, slides = image files sorted by name); per-user card state in `neo_explica_estado`, opens in `neo_explica_views`; rotation rule in `src/lib/neoExplica.ts`. Why: content team uploads images without code changes and the card choice stays testable.
- No offline service worker: `public/sw.js` is a kill-switch that clears old cached versions; home-screen install uses `public/manifest.webmanifest` only. Why: the old offline cache kept phones on stale versions after publishing.
- App images ship as files in `src/assets` (not lovable-assets pointers). Why: Capacitor native builds load the bundle locally and cannot reach hosted asset paths.
- Neo's app knowledge (method, journeys, screens) lives in section 6 of `SYSTEM_PROMPT` and per-user engagement in `buildUserContext`, both in `supabase/functions/chat/index.ts`; Home suggestion rules live in `src/lib/neoSuggestions.ts`. Why: when the app's method or screens change, Neo must be updated in one place and redeployed.
- Theme images (`habitos_jornada.imagem_nome`) live in the private `images` bucket and load through signed links via `useThemeImage` (`src/hooks/useThemeImage.tsx`, signing in `src/lib/themeImage.ts`); never use public URLs for them. Why: the workspace blocks public buckets, so public links return errors.
- Mission copy uses `missao_principal` and `missao_secundaria` through `getMissionCopy`, with legacy description fallback, in a shared `MissionDialog`; playback-ended transitions capture the played theme and retain content gating. Why: Home and Journey must show identical instructions without confusing 85% completion with actual playback end or advancing to the wrong theme.
- Main-tab surfaces use `shadow-primary` for cards and `shadow-surface` for compact actions instead of decorative outlines; keep focus and selection indicators. Why: shared semantic shadow tokens keep the three tabs visually consistent.
- JourneyRail owns horizontal navigation with a separate overlay Button outside theme cards. Why: arrow taps advance the rail without opening content.
- All journeys are open in the Jornada tab; the Home focus comes from `pickFocus` using the onboarding journey and `ultima_jornada_usuario`; Progresso layout/auto-zero/counter remain driven by onboarding and ritual date in `computeProgressMode`. Why: choosing content must not reset progress or imply that the user stopped smoking.
- Progress counters and charts use the same onboarding window; `computeProgressMode` separates an explicit ritual date from the total distinct zero-log days. Why: recorded smoke-free days are cumulative achievements, not proof of continuous abstinence or a ritual.
- `RitualPrompt` presents the full invitation at the end of Home and a compact unframed invitation inside Progress potential, opening the existing date picker. Why: both entry points stay consistent without inferring a quit date from zero logs.
- Journey metadata stays in `habitos_jornada`; `src/lib/journeys.ts` owns presentation catalog, content flags, video bucket and completion rules shared by Home/Jornada. Intensive days use a separate tracking prefix and require video plus hypnosis. Why: new journeys must not inherit mission/mural or collide with legacy progress.
